* Philosophy

I use Emacs constantly since 2010 and I really like the idea of starter kits. I've used distributions like [[https://www.spacemacs.org/][Spacemacs]] and [[https://github.com/hlissner/doom-emacs][Doom Emacs]] until I conclude that they usually make a lot assumptions that are not fit for what I need.

Of course you can try fork some of those kits in the wild and try to trim the pieces you don't want, but I found this to be too time consuming. So I decided to rewrite my own configuration as a starter-kit, to slowly organize the code I have and maybe make it useful for someone else besides me.

Since I'm starting doing this effectively during the social distancing measures taken after COVID-19 world pandemic I decided to call it =Pathogen=.

The philosophy is to be:
- Stable :: Prefer built-in features and well-established packages
- Simple :: Clear, straightforward configuration without magic
- Easy to understand :: Comprehensive documentation and comments

This means that by default it won't have all the fanciness of Spacemacs or Doom. Unless you are willing to accept a huge amount of code/packages without understanding them well (which makes you pass through hell when something go astray), as an Emacs user you're going to have to get minimally comfortable seeking out new pieces of elisp code, bringing them in and configuring them. The Starter Kit should serve mainly as a guidance in this process by giving hints as to where to start and what to look for.

* Requirements

- *GNU Emacs* 27.1 or higher (29+ recommended for tree-sitter and eglot)
- *Git* 2.23 or higher
- *Internet connection* for initial package installation
- *Optional*: LSP servers for language-specific features

* Installation

** Basic Installation

1. Backup your existing Emacs configuration (if any):
   #+begin_src bash
   mv ~/.emacs.d ~/.emacs.d.backup
   mv ~/.emacs ~/.emacs.backup  # if you have this file
   #+end_src

2. Clone this repository:
   #+begin_src bash
   git clone https://gitlab.com/padawanphysicist/pathogen-emacs.git ~/.emacs.d
   #+end_src

3. Launch Emacs!
   #+begin_src bash
   emacs
   #+end_src

** First-time Startup

The first startup will take 30-60 seconds as Elpaca bootstraps and installs all packages:

1. *Bootstrap Phase*: Elpaca clones itself from GitHub
2. *Package Installation*: All configured packages are downloaded and built
3. *Compilation*: Byte-compilation of packages for better performance
4. *Dashboard Display*: You'll see the Pathogen dashboard when complete

You'll see progress messages in the =*Messages*= buffer and =*elpaca-log*= buffer.

** Verifying Installation

After Emacs starts, check that everything loaded correctly:

1. Check the startup message in the echo area (bottom of screen) - should show load time
2. Run =M-x pathogen/validate-config= to check for common issues
3. Run =M-x pathogen/show-load-times= to see module load times

If you encounter errors, see the [[#troubleshooting][Troubleshooting]] section.

* Configuration Structure

** Core Files

| File               | Purpose                                      | When Loaded       |
|--------------------+----------------------------------------------+-------------------|
| =early-init.el=    | Pre-initialization, UI setup, GC tuning      | Before GUI init   |
| =init.el=          | Main entry point, loads modules              | After GUI init    |
| =~/.pathogen.el=   | User customizations (optional)               | After modules     |
| =custom.el=        | Emacs customization system output            | Not loaded by us  |
| =pathogen-vars.el= | Shared variables between early-init and init | Very early        |

** Module System

Pathogen uses a numbered module system where each module has a specific responsibility. Modules are located in the =pathogen/= directory:

| Module                       | Purpose                               | Dependencies         |
|------------------------------+---------------------------------------+----------------------|
| =00-user-interface.el=       | Visual appearance, frame parameters   | None                 |
| =01-editor.el=               | Core editor behavior, built-in modes  | None                 |
| =02-package-manager.el=      | Elpaca and use-package setup          | None                 |
| =03-setup-packages.el=       | External package configurations       | 02-package-manager   |
| =04-custom-functions.el=     | Utility functions and debugging tools | None                 |

** Load Order and Dependencies

Modules are loaded in numerical order by =init.el=:

1. *early-init.el* loads first (Emacs does this automatically)
   - Sets up UI before frame creation (prevents flashing)
   - Configures GC thresholds for faster startup
   - Disables file-name-handler-alist temporarily
     
2. *init.el* orchestrates module loading:
   #+begin_src elisp
   (pathogen--load-module "00-user-interface")
   (pathogen--load-module "01-editor")
   (pathogen--load-module "02-package-manager")
   (pathogen--load-module "03-setup-packages")
   (pathogen--load-module "04-custom-functions")
   #+end_src

3. *~/.pathogen.el* loads last (if it exists)
   - Your personal customizations
   - Override any settings
   - Add custom packages or functions

*Critical*: Module =02-package-manager.el= MUST load before =03-setup-packages.el= because packages need Elpaca and use-package to be configured first.

* Customization

** User Configuration File

Create =~/.pathogen.el= for your personal customizations:

#+begin_src elisp
;;; ~/.pathogen.el --- Personal Emacs configuration

;; Example: Override theme
(load-theme 'doom-gruvbox t)

;; Example: Set custom font
(pathogen/set-font
 '(("JetBrains Mono" . 12)
   ("Fira Code" . 12)
   ("Menlo" . 12)))

;; Example: Add custom keybindings
(global-set-key (kbd "C-c m") 'magit-status)

;; Example: Configure LSP for additional languages
(with-eval-after-load 'eglot
  (add-to-list 'eglot-server-programs
               '(ruby-mode . ("solargraph" "stdio"))))

;; Example: Custom variables
(setq pathogen-enable-lsp nil)  ; Disable LSP if desired
#+end_src

This file is loaded *after* all modules, so you can override any settings.

** Adding Packages

To add a new package, edit =pathogen/03-setup-packages.el=:

#+begin_src elisp
;; Add at the end of the file, before (provide '03-setup-packages)
(use-package package-name
  :defer t  ; Lazy load when possible
  :bind ("C-c x" . package-command)  ; Optional keybinding
  :custom
  (package-variable value "Documentation")
  :config
  (package-mode 1))
#+end_src

Then restart Emacs or run =M-x pathogen/reload-config=.

** Removing Packages

To remove a package:

1. Comment out or delete its =use-package= declaration in =03-setup-packages.el=
2. Restart Emacs or run =M-x pathogen/reload-config=
3. Optionally remove the package directory: =M-x elpaca-delete= → select package

** Creating Custom Modules

You can add your own modules following the naming convention:

1. Create =pathogen/05-my-module.el=:
   #+begin_src elisp
   ;;; 05-my-module.el --- My custom module -*- lexical-binding: t; -*-
   ;;
   ;; Module: My Custom Module (05)
   ;; Purpose: Custom functionality
   ;; Dependencies: None
   ;;
   ;;; Code:

   ;; Your code here

   (provide '05-my-module)
   ;;; 05-my-module.el ends here
   #+end_src

2. Load it in =init.el=:
   #+begin_src elisp
   (pathogen--load-module "05-my-module")
   #+end_src

** Feature Flags

Selectively enable/disable feature categories by defining flags in =~/.pathogen.el=:

#+begin_src elisp
;; Disable specific features
(defvar pathogen-enable-lsp nil
  "Disable LSP support.")

(defvar pathogen-enable-snippets nil
  "Disable yasnippet.")
#+end_src

Then wrap corresponding packages in =03-setup-packages.el=:

#+begin_src elisp
(when (bound-and-true-p pathogen-enable-lsp)
  (use-package eglot
    :hook ((python-mode . eglot-ensure))
    ...))
#+end_src

Available flags (define any as =nil= to disable):
- =pathogen-enable-completion= - Vertico, Consult, Embark, Corfu
- =pathogen-enable-navigation= - Avy, Ace-window
- =pathogen-enable-version-control= - Magit, diff-hl
- =pathogen-enable-editing-enhancements= - Multiple-cursors, visual-regexp
- =pathogen-enable-lsp= - Eglot, tree-sitter
- =pathogen-enable-snippets= - Yasnippet
- =pathogen-enable-syntax-checking= - Flycheck
- =pathogen-enable-ui-enhancements= - Which-key, dimmer, rainbow-delimiters

* Key Features & Workflows

** Completion Framework

Pathogen uses a modern completion stack:

- *Vertico*: Vertical completion UI
- *Consult*: Enhanced commands (finding, searching, preview)
- *Orderless*: Flexible matching (space-separated patterns)
- *Embark*: Contextual actions on completions
- *Corfu*: In-buffer completion popup
- *Marginalia*: Rich annotations in completion

*** Basic Usage

- =M-x= - Execute command (with live filtering)
- =C-x C-f= - Find file (with directory navigation)
- =C-x b= - Switch buffer (with preview)
- =C-s= - Search in buffer

*** Orderless Matching

Type space-separated patterns in any order:

- =py mod= matches "python-mode", "my-python-module"
- =^py= matches beginning (python-mode, but not my-python)
- =py$= matches end (numpy, scipy)

* Package Update Workflow

Pathogen uses Elpaca for package management. Here's how to safely update your packages.

** Updating All Packages

The recommended way to update packages:

#+begin_src elisp
M-x pathogen/update-packages
#+end_src

This function:
- Updates all installed packages to their latest versions
- Provides confirmation before starting
- Shows progress in the =*elpaca-log*= buffer
- Includes comprehensive guidance in the docstring

** Before Updating

1. *Backup your work*:
   - Commit your configuration to git (if using version control)
   - Save all buffers in Emacs
   - Note current package versions: =M-x elpaca-log=

2. *Check for breaking changes*:
   - Review package changelogs for major updates
   - Check if any packages have deprecated features you use

** During Update

- Monitor progress: =M-x elpaca-log=
- The process may take several minutes
- Don't interrupt Emacs during updates

** After Updating

1. Check for errors in =*Messages*= buffer
2. Run =M-x pathogen/validate-config= to check for issues
3. Test your workflow thoroughly
4. If issues arise, see Rollback Procedures below

** Updating a Single Package

To update just one package:

#+begin_src elisp
M-x elpaca-update RET package-name
#+end_src

** Rollback Procedures

If an update breaks something, you have several options:

*** Method 1: Delete and Reinstall

#+begin_src elisp
M-x elpaca-delete RET package-name RET
#+end_src

Then restart Emacs. The package will reinstall from its recipe.

*** Method 2: Manual Removal

#+begin_src bash
rm -rf ~/.emacs.d/elpaca/builds/package-name
rm -rf ~/.emacs.d/elpaca/repos/package-name
#+end_src

Restart Emacs to reinstall.

*** Method 3: Git Rollback

If your configuration is in git:

#+begin_src bash
git log  # Find commit before update
git reset --hard COMMIT_HASH
#+end_src

** Viewing Package Status

Check individual package status:

#+begin_src elisp
M-x pathogen/check-package RET package-name
#+end_src

View all package logs:

#+begin_src elisp
M-x elpaca-log
#+end_src

** Rebuilding Packages

If packages have compilation issues after updates:

#+begin_src elisp
M-x pathogen/rebuild-packages
#+end_src

This rebuilds all packages, fixing issues from:
- Emacs version upgrades
- Corrupted bytecode
- Compilation errors

** Update Schedule

Recommended update frequency:
- *Monthly*: For most users, monthly updates balance stability with new features
- *Weekly*: For those who want latest features and don't mind occasional issues
- *As needed*: Update specific packages when you need new features or bug fixes

Always test after updates before doing critical work.

* Troubleshooting

** Slow Startup

1. Check module load times:
   #+begin_src elisp
   M-x pathogen/show-load-times
   #+end_src

2. Profile initialization:
   #+begin_src elisp
   M-x pathogen/profile-init
   #+end_src
   Copy and run the generated command in terminal.

3. Common causes:
   - Too many packages loading immediately (use =:defer t=)
   - Heavy packages without lazy loading (LSP, completion)
   - Network issues during package updates

4. Optimize:
   - Use feature flags to disable unused categories
   - Defer more packages with =:defer t= or =:hook=
   - Consider =use-package-always-defer= (see =02-package-manager.el=)

** Package Installation Fails

1. Check Elpaca log:
   #+begin_src elisp
   M-x elpaca-log
   #+end_src

2. Verify internet connectivity and GitHub access:
   #+begin_src bash
   ping github.com
   #+end_src

3. Try rebuilding the package:
   #+begin_src elisp
   M-x elpaca-rebuild RET package-name
   #+end_src

4. Nuclear option - rebuild everything:
   #+begin_src elisp
   M-x pathogen/rebuild-packages
   #+end_src

** LSP Not Working

1. Verify language server is installed:
   #+begin_src bash
   # Python
   pip list | grep python-lsp-server

   # JavaScript/TypeScript
   npm list -g | grep typescript-language-server

   # Rust
   rustup component list | grep rust-analyzer
   #+end_src

2. Check eglot connection:
   #+begin_src elisp
   M-x eglot  ; Manually start in a source file
   #+end_src

3. View eglot events buffer:
   #+begin_src elisp
   M-x eglot-events-buffer
   #+end_src

4. Verify server configuration:
   #+begin_src elisp
   M-x describe-variable RET eglot-server-programs
   #+end_src

** Fonts Not Loading

1. Verify font is installed:
   #+begin_src bash
   fc-list | grep "Font Name"
   #+end_src

2. Check if display is graphical:
   #+begin_src elisp
   M-: (display-graphic-p)  ; Should return t
   #+end_src

3. Try setting font manually:
   #+begin_src elisp
   M-x pathogen/set-font
   #+end_src

4. For daemon mode, ensure hooks are set:
   - Font setting should be in =after-init-hook=
   - For new frames: =server-after-make-frame-hook=

** Configuration Errors

1. Check for errors during startup:
   #+begin_src elisp
   M-x view-echo-area-messages  ; or switch to *Messages* buffer
   #+end_src

2. Validate configuration:
   #+begin_src elisp
   M-x pathogen/validate-config
   #+end_src

3. Test in clean environment:
   #+begin_src elisp
   M-x pathogen/test-config
   #+end_src

4. Start Emacs with debug mode:
   #+begin_src bash
   emacs --debug-init
   #+end_src

5. Check specific module:
   #+begin_src elisp
   M-: (load "~/.emacs.d/pathogen/MODULE-NAME.el")
   #+end_src

* Performance Optimization

Pathogen includes several performance optimizations:

** Startup Optimizations

1. *GC Threshold Tuning* (=early-init.el=)
   - Raises GC threshold to 100MB during startup
   - Reduces to 10MB after init
   - Prevents GC pauses during initialization

2. *File-name-handler-alist Optimization* (=early-init.el=)
   - Temporarily disabled during startup
   - 30-50% faster startup time
   - Restored after init completes

3. *Lazy Loading* (=03-setup-packages.el=)
   - Most packages deferred until needed
   - Use =:hook=, =:mode=, =:bind= for automatic deferring
   - Explicit =:defer t= where appropriate

** Runtime Optimizations

1. *Auto-save Strategy* (=01-editor.el=)
   - Modern =auto-save-visited-mode= instead of traditional auto-save
   - No #filename# clutter
   - 5-second interval

2. *JIT Lock Stealth Time* (=01-editor.el=)
   - Fast syntax highlighting (0.2s)
   - Improves scrolling in large files

3. *Completion Performance* (=03-setup-packages.el=)
   - Vertico with minimal processing
   - Orderless for efficient matching
   - Corfu with small delay
